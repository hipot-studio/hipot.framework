Ресайзер изображений hiImg
------------------------------------------------------

Документация по методам трансформации и назначение класса см в статье [Constantly Integrable Modifier of Graphics](https://www.hipot-studio.com/Codex/cimg-constantly-integrable-modifier-of-graphics/)

> Статья описывает первый релиз класса и частично устарела. В старой версии режимом по умолчанию был `FULL`, а в текущем `doResize()` по умолчанию используется `M_CROP`. Возможность добавлять режим через метод `methodИМЯ_МЕТОДА()` также отсутствует: для дополнительной обработки используйте callback последнего аргумента `doResize()`.

## Методы трансформации

Метод передаётся четвёртым аргументом `doResize()` и задаёт, как исходное изображение должно быть вписано в размеры `$w` и `$h`:

```php
$result = $imgResizer->doResize($image, $w, $h, hiImg::M_CROP, true);
```

| Метод | Что происходит | Размер результата | Когда использовать |
|---|---|---|---|
| `M_CROP` | Изображение масштабируется с сохранением пропорций. Выходящие за целевую область части обрезаются относительно центра. | Ровно `$w × $h`. Если `$h === null`, создаётся квадрат `$w × $w`. | Превью и карточки, где все изображения должны занимать одинаковую область без полей. |
| `M_CROP_TOP` | То же, что `M_CROP`, но область кадрирования прижата к верхнему краю. Нижняя часть изображения обрезается первой. | Ровно `$w × $h`. | Портреты и изображения, где важное содержимое находится сверху. |
| `M_FULL` | Изображение пропорционально вписывается в заданную область, недостающая часть дополняется холстом. Увеличение маленького оригинала разрешено. | Ровно `$w × $h`. | Каталоги и галереи, где нельзя обрезать исходник, но нужен единый размер ячейки. |
| `M_FULL_S` | Аналог `M_FULL`, но маленький оригинал не увеличивается (`upsize` запрещён). Свободное пространство заполняется холстом. | Ровно `$w × $h`. | Логотипы, иконки и небольшие изображения, для которых увеличение ухудшит качество. |
| `M_PROPORTIONAL` | Пропорциональное изменение размера без обрезки и без добавления холста. Можно передать только ширину или только высоту, указав вторую величину как `null`. | Определяется пропорциями исходника. | Адаптивные изображения, SEO-картинки и обычное ограничение по ширине либо высоте. |
| `M_STRETCH` | Изображение растягивается точно до переданных размеров без сохранения пропорций. | Ровно `$w × $h`. | Только когда допустимо искажение пропорций. |

После каждой трансформации применяется лёгкое повышение резкости (`sharpen(6)`). Для `M_FULL` и `M_FULL_S` используется почти прозрачный светлый холст. Чтобы сохранить его прозрачность, задайте `saveAlpha => true`: итоговый файл будет сохранён как PNG, если формат явно не переопределён через `decodeToFormat`.

### Как выбрать метод

- Нужен точный размер и допустима обрезка — `M_CROP` или `M_CROP_TOP`.
- Нужен точный размер, но обрезать изображение нельзя — `M_FULL`.
- То же самое, но нельзя увеличивать маленький оригинал — `M_FULL_S`.
- Нужны исходные пропорции без фиксированного холста — `M_PROPORTIONAL`.
- Нужно принудительно заполнить размер с возможным искажением — `M_STRETCH`.

Ширина и высота должны быть положительными. Для `M_PROPORTIONAL` одну из величин можно оставить `null`; для режимов с фиксированной областью лучше всегда задавать обе.


## Входные данные и результат

В `$image` можно передать ID файла Bitrix, путь относительно корня сайта, абсолютный путь, URL либо массив файла Bitrix с ключом `SRC`.

При `$retAr = false` метод возвращает путь к созданной копии. При `$retAr = true` возвращается массив, совместимый по основным ключам с `CFile::ResizeImageGet()`:

```php
[
    'SRC' => '/upload/himg_cache/catalog/abc/.../image.webp',
    'WIDTH' => 800,
    'HEIGHT' => 600,
    'src' => '/upload/himg_cache/catalog/abc/.../image.webp',
    'width' => 800,
    'height' => 600,
]
```

Для изображения, переданного как ID файла Bitrix, в массив дополнительно включается `ID`.

Результаты сохраняются в `/upload/himg_cache/`. Параметр `tag` создаёт отдельную подпапку кеша, например `/upload/himg_cache/catalog/`, поэтому кеш конкретного компонента или шаблона можно удалить независимо от остальных копий. В ключ кеша входят исходные аргументы трансформации и настройки экземпляра (`tag`, `saveAlpha`, `decodeToFormat`, `jpgQuality`).

## Параметры экземпляра

| Параметр | Назначение |
|---|---|
| `tag` | Группирует созданные копии в отдельной подпапке кеша. |
| `jpgQuality` | Качество сохранения; при `0` используется настройка `image_resize_quality` главного модуля Bitrix. |
| `decodeToFormat` | Принудительный формат результата: `webp`, `png`, `jpeg`, `jpg` или `gif`. |
| `saveAlpha` | Сохраняет прозрачность холста методов `M_FULL` и `M_FULL_S`, переводя результат в PNG. |

### Ресайз с наложением изображения

`doResizeOverlay()` сначала выполняет выбранную трансформацию, а затем накладывает изображение `$overlay`:

```php
$result = $imgResizer->doResizeOverlay(
    $image,
    '/upload/watermark.png',
    'bottom-right',
    1200,
    800,
    hiImg::M_CROP,
    true,
);
```

Поддерживаются позиции `center`, `top-left`, `top`, `top-right`, `left`, `right`, `bottom-left`, `bottom` и `bottom-right`. В отличие от первого релиза, сокращения `lt`, `rb` и произвольные координаты не поддерживаются. Путь к накладываемому изображению должен быть абсолютным либо относительным к корню сайта; ID файла Bitrix для `$overlay` текущая реализация не принимает.

### Дополнительная обработка перед сохранением

Последний аргумент `doResize()` принимает callback, которому передаётся текущий экземпляр `Img`. Через `getProcessEngine()` доступен объект `Intervention\Image\Image`:

```php
$result = $imgResizer->doResize(
    $image,
    1200,
    800,
    hiImg::M_CROP,
    false,
    static function (hiImg $img): void {
        $img->getProcessEngine()->brightness(5);
    },
);
```

Callback входит в идентификатор кеша. Для стабильного кеширования предпочтительна именованная функция либо статическое замыкание, не захватывающее изменяемое внешнее состояние.

## Рассмотрим на примерах использования:

1/ В шаблоне компонента:
```php
// шаблон компонента, template.php
use Hipot\Utils\Img as hiImg;
$imgResizer = hiImg::getInstance([
    'tag'            => basename(__DIR__),  // уменьшенная копия будет сохранена в подпапке с именем шаблона
    'jpgQuality'     => 65,
    'decodeToFormat' => 'webp'
]);
$imgSmall = $imgResizer->doResize($arItem['PREVIEW_PICTURE']["ID"], 74, null, hiImg::M_PROPORTIONAL, true);
$imgBig = $imgResizer->doResize($arItem['PREVIEW_PICTURE']["ID"], 100, null, hiImg::M_PROPORTIONAL, true);
```
2/ Старый способ использования без создания объекта-сервиса:
```php
Img::oneResizeParams([
    'tag'            => 'test.detail',
    'decodeToFormat' => 'webp',
    'saveAlpha'      => true
]);
$pic_answer = Img::Resize($val, 225, 186, Img::M_FULL_S, true);
```
3/ Если нужно два формата, можно создать два объекта:
```php
// модификатор шаблона, result_modifier.php
use Hipot\Utils\Img as hiImg;
if ((int)$arResult["DETAIL_PICTURE"]["ID"] > 0) {
    $imgResizerJpg = hiImg::getInstance([
        'decodeToFormat' => 'jpg'
    ]);
    $imgResizer = hiImg::getInstance([
        'decodeToFormat' => 'webp'
    ]);
    
    // тег можно поставить и так (как и поменять другие атрибуты, см. методы set...()    
    $imgResizer->setTagInternal(basename(__DIR__ ));
    $arResult['SEO_IMAGE'] = $imgResizerJpg->doResize($arResult['DETAIL_PICTURE']["ID"], 1000, null, hiImg::M_PROPORTIONAL, true);
    
    $imgResizer->setTagInternal(basename(__DIR__ ) . '_mob');
    $arResult["DETAIL_PICTURE_MOBILE"] = $imgResizer->doResize($arResult['DETAIL_PICTURE']["ID"], 360, null, hiImg::M_PROPORTIONAL, true);
    
    $imgResizer->setTagInternal(basename(__DIR__ ) . '_dp');
    $arResult["DETAIL_PICTURE"] = $imgResizer->doResize($arResult['DETAIL_PICTURE']["ID"], 800, null, hiImg::M_PROPORTIONAL, true);
}
unset($imgResizer, $imgResizerJpg);
```
